## Routes and Data Flow

Active browser routes:

- `/` -> `Dashboard`
- `/preferences` -> placeholder `Preferences`
- `/about` -> `About`

`Dashboard` owns search text, the selected folder or collection (mutually exclusive), camera/lens/ISO/month filters, and the active scan job ID. It queries `folders`, `filterOptions`, `photos`, and `searchPhotos` through tRPC. Search is reactive: a non-empty query enables `searchPhotos` (with the selected folder or `collectionId` and camera/lens/ISO/month filters) and disables the `photos` library query; `filterOptions({ folder })` stays active so filters remain selectable during search.

The dashboard scan mutation receives an Inngest `jobId`; `useJobProgress` obtains a Realtime token through `realtimeToken` and subscribes to `job:{jobId}`. An advancing `processing.current` invalidates photos, folders, and filter options: the first advance refreshes immediately, and subsequent advances coalesce into a trailing refresh at most once per second. Duplicate or stale progress does not trigger another processing refresh. Entering `scan-complete` or the first `embedding` phase refreshes the library immediately, without waiting for embeddings to finish.

The token query is enabled when a job starts; the subscription waits for its result. For self-hosting, the API's optional `realtimeToken.baseUrl` supplies a client-reachable origin, attached through a keyless SDK client on initial and refreshed tokens. Progress is decoded from the Realtime message's `data` envelope. Server event/signing keys must never be bundled.

The hook also polls durable `scanStatus` every 1500 ms, including while Realtime is connected, so token failures, disconnects, or missed messages do not prevent progress and library refreshes. Polling stops when durable status is terminal or the job is missing; token queries and subscriptions are disabled in those states. Failed token queries retry periodically, and subscription token refresh preserves the self-hosted origin.

Progress is accepted monotonically by phase and count for the active job; delayed processing messages cannot move an embedding or terminal job backward, and durable terminal status takes precedence. `scan-complete` is the handoff to indexing, not a terminal state, and `embedding` remains active. Only `completed` and `failed` are terminal; a missing durable job is surfaced as failed. Terminal progress cancels pending coalesced refreshes and invalidates library, folder, filter, and search queries once per job. Changing jobs or unmounting cancels old refresh timers.

See [import performance](../../docs/import-performance.md) for measured native/persistence timings and the separate real API/Inngest/web smoke; these are not interchangeable with mocked E2E results.

The tRPC client uses `httpBatchLink` for queries/mutations and `unstable_httpSubscriptionLink` for subscriptions. Both use `superjson` and `${API_URL}/api/trpc`.

## Current UI Behavior

- The layout has a left library panel, center content, right metadata panel, toolbar, and optional loupe filmstrip.
- The toolbar's primary scan action is incremental: it processes new/changed photos and repairs incomplete processing. The secondary **Reprocess all photos…** action opens a confirmation sheet explaining that thumbnails and embeddings will be regenerated, originals remain untouched, and the operation takes longer. Only confirming sends `scan({ force: true })`; cancelling sends nothing. Both actions are disabled while the mutation or scan/indexing job is active.
- Panel widths are currently fixed at 256px left, 288px right, and 96px filmstrip height in `PanelLayout`. Persisted width/height state is not applied to those classes.
- Grid click sets one active photo; double-click opens loupe. There is no multi-photo selection state.
- Loupe supports fit, fill, 100% zoom modes, keyboard navigation, and metadata display.
- The filmstrip is rendered when loupe mode is active and its visibility is enabled.
- The Type control (All/RAW/Standard/Video; `filterRaw` sent only when not `all`), folders, and camera/lens/ISO/date filters combine as query filters for both the library and search. The library panel stays fully visible during search; changing the folder or a filter re-runs the search with that scope. A results header shows the count, query, and scope (e.g. `12 results for “beach” in photos/2024 · Sony A7III · RAW only`) with a ✕ that clears the search and returns to the library grid with the same folder and filters. RAW photos show their format badge in both grid and loupe.
- **RAW+JPEG pairs**: the API stacks a RAW and its same-folder, same-stem standard partner into one photo (the RAW is omitted whenever its partner matches the same filters) and reports `pairedPhotoId`/`pairedFormat` on every photo DTO. The web never stacks or hides photos itself. `rawBadge` shows `${raw}+${standard}` (e.g. `ARW+JPG`) on paired photos in the grid, loupe, duplicate cards, and the metadata RAW section, and `R+J` (full label as tooltip) in the filmstrip; unpaired RAWs keep `rawFormat || "RAW"`. The metadata panel's RAW section adds a **Pair** row with the partner's filename (fetched with `trpc.photo({ id: pairedPhotoId })`) and format. Curation of a paired photo is applied to both files by the API; the client sends only the shown ID.
- **Videos and Live Photos**: photo DTOs carry `mediaType` (`photo`/`video`), `durationMs`, `videoCodec`, and `motionVideoId`; the API hides Live Photo motion clips and sets `motionVideoId` on the visible still (the web never hides them itself). `formatDuration` floors to whole seconds: `m:ss`, `h:mm:ss` from one hour, `0:00` for null/negative/non-finite. Grid tiles show a play-glyph duration badge bottom-right beside the rating/flag badge (accessible label e.g. "Video, 1 minute 5 seconds"; "Video" when unknown) and a `LIVE` badge ("Live Photo") top-right for stills with `motionVideoId`; filmstrip tiles show the duration badge. The loupe renders a video as `<video controls playsInline preload="metadata">` with `src` = `getFullImageUrl` (the `/file` route, Range-capable) and `poster` = the large thumbnail, paused by default; it is keyed by photo ID and paused (source dropped) on unmount, so arrows, `Escape`, `G`, or search release it. **LIVE** plays the clip (muted, inline, once) over the still and returns to it on `ended`/error or when leaving the photo. `Space` toggles play/pause only while the loupe shows a video (ignored in inputs; `Shift+Space` stays the filmstrip toggle). The Type control's **Video** sends `filterRaw: "video"` (scope label "Videos only"); the metadata File section adds Duration and uppercased Codec rows for videos; the Export menu offers only Original for videos and `Shift+D` downloads a video's original.
- **Find similar** (metadata panel button or `S` with an active photo, ignored while typing) queries `similarPhotos({ photoId, limit: 60 })` and shows a dismissible "Similar to …" grid. ✕, `Escape` in grid view, a non-empty search, folder selection, or starting a scan exits it; `indexed: false` shows a run-a-scan message.
- **Export** (`src/components/PhotoExportMenu.tsx`): the metadata panel's top action row (beside Find similar) holds an **Export** dropdown whenever a photo is active, so it works in grid-with-active-photo and loupe. Its items "Original (NAME.EXT)", "JPEG, 2048 px", and "JPEG, 1024 px" are `<a href download>` anchors to `exportPhotoUrl(id, size)` (`/api/photos/:id/export?size=original|2048|1024`); `download` is the original name or `{stem}_{size}.jpg` (RAW originals keep their RAW name). `Shift+D` (with an active photo, ignored while typing) downloads the JPEG 2048 through a detached anchor. Downloads never use fetch/blob, so large originals stream to disk; the API's `Content-Disposition` names the file when `download` is ignored cross-origin. Each collection row's "…" menu has **Download as ZIP**, which expands inline (the scrolling left panel would clip a fly-out) to Originals / JPEG 2048 / JPEG 1024 anchors to `exportCollectionUrl(id, size)` (`/api/collections/:id/export`) with `download="{name}.zip"`.
- **Curation** (`src/hooks/use-photo-curation.ts`): with an active photo and focus outside inputs, `0`-`5` set the rating, `P` picks, `X` rejects, and `U` unflags; the metadata panel's Rating stars (clicking the current star clears to 0) and Pick/Reject toggles do the same. `trpc.setPhotoCuration` is applied optimistically to every cached `photos`/`searchPhotos`/`similarPhotos` list and the active photo, rolled back on error, and invalidated on settle. Grid cells show a ★n/flag badge; rejected photos are dimmed in the grid and filmstrip. Filter By's Rating (Any, ★1+…★5) and Flag (Any/Picks/Rejected/Unflagged) controls send `minRating`/`flag` to `photos` and `searchPhotos` and join Filters active, Clear all, and the search header scope.
- **Collections** (`src/hooks/use-collections.ts`): the library panel's Collections section (between Folders and Filter By) lists each collection with its photo count. "+" opens an inline name field (Enter creates, Escape cancels; a case-insensitive duplicate shows the API's `CONFLICT` inline); each row's hover "…" menu offers inline Rename and Delete (confirmation sheet; photos are never touched, and deleting the selected collection returns to All Photos). Selecting a collection sends `collectionId` on `photos`/`searchPhotos`, clears the folder (and vice versa; All Photos clears both), and shows a collection header or `… in <name>` search scope. The metadata panel shows the active photo's collection chips (`collectionsForPhoto`) and an "Add to collection" popover whose checkboxes add/remove immediately, plus "New collection…" which creates the collection containing the photo. `B` (focus outside inputs) toggles the active photo in the last collection added to or created this session; it does nothing before one exists. Membership changes update `collectionsForPhoto` optimistically, then invalidate `collections`, `collectionsForPhoto`, and `photos`/`searchPhotos` queries scoped to that `collectionId`, so a photo removed while viewing the collection leaves the grid. Failures appear inline under the chips.
- **Smart albums** (`src/hooks/use-smart-albums.ts`): the library panel's Smart Albums section (directly under Collections) lists `smartAlbums` by name with a live `photoCount` badge, or a search icon for query albums (`photoCount: null`). Each row's hover "…" menu offers inline Rename (`updateSmartAlbum`; a case-insensitive duplicate shows the API's `CONFLICT` inline) and Delete (confirmation sheet; no photos change, and the current folder/filters/search stay as they are). Whenever any library filter, a folder, or a search query is active, **Save as Smart Album…** appears below the Filters active/Showing indicators. It opens a name dialog that saves the folder and filters (never the collection) as `filters`, plus the trimmed search text as `query`. Clicking an album replaces the folder, filters, and search with its saved ones; clears collection, Find similar, and Review; marks the row `aria-current`; and shows a `smart-album-header` with the name, plus the search header for query albums, which open with `searchPhotos` limit 100. Any later change to folder, filters, search, collection, or mode deselects it for good (the album is a starting point, not a lock), and the header ✕ returns to the unfiltered library. Scan progress, curation, and junk rejections invalidate `smartAlbums` so counts stay live.
- **Auto tags**: Filter By's Tags section (after Flag, before Camera) lists `filterOptions.tags` (folder-scoped, count desc) with counts, top 12 then "Show all (N)"/"Show fewer"; a selected tag outside the visible list stays listed. Selection is single (clicking again clears) and sends `tag` (slug) on `photos` and `searchPhotos`; it joins Filters active, Clear all, and the search header scope (`· #beach`). Slugs display as Title Case with hyphens as spaces (`night-sky` → "Night sky", `formatTagName`). The metadata panel's Tags row shows `photoTags` chips in score order ("No tags yet" when empty); clicking one sets the tag filter, exits similar mode, and returns to the grid. Terminal scan progress also invalidates `photoTags`.
- **Places** (offline GeoNames place names): Filter By's Places section (after Tags) appears when `filterOptions.countries` is non-empty or a country/place filter is active. Countries (folder-scoped, photo-row counts, count desc) show the top 12 then "Show all (N)"/"Show fewer"; selection is single, and the selected country lists its cities from `filterOptions.places` (filtered by `countryCode`, previewed the same way) beneath it. Selecting a city sets `place` (geoname id) and keeps `country`; clearing or changing the country clears `place`. `country`/`place` are sent on `photos`, `searchPhotos`, and `photoLocations`, saved and restored in smart albums, and shown as removable chips (country name, city name) under Filters active; Clear all clears both. The search header and smart album summary show the city, or the country when no city is selected. The metadata Location section shows a Place row from `photoPlace` above Latitude, labelled city, then region (omitted when null or equal to the city), then country ("Kyoto, Japan", "Portland, Oregon, United States"); clicking it sets the country + city filter, exits similar mode/Review/Duplicates, and returns to the grid. No row renders when `place` is null. Terminal scan progress also invalidates `photoPlace`.
- **On this day**: while the grid shows the whole library (no library filter, folder, search, collection, smart album, Find similar, Review/Duplicates, map area, or capture date; grid view only), `onThisDay({ date })` is requested with the browser's local `YYYY-MM-DD` (never UTC) and an "On this day" strip above the grid shows one card per year in API order: `small` cover thumbnail (`getThumbnailUrl` with the cover's `thumbnailUpdatedAt`), "1 year ago"/"N years ago", the date ("Jun 15, 2025", built in local time without zone conversion), and "N photos". No years render no strip. Clicking a card sets the `capturedDate` filter, sent on `photos`, `searchPhotos`, and `photoLocations`, shown as a removable chip under Filters active (Clear all clears it) and as `· Jun 15, 2025` in the search header. It is a view scope like `bounds`: never saved in smart albums (alone it does not offer **Save as Smart Album**) and an applied album deselects while it is set. Scan refreshes, curation, junk rejections, and duplicate keeps invalidate `onThisDay`.
- **Events** (auto-detected by the API): the library panel's Events section (after Smart Albums, collapsible) lists `events({ folder? })`, scoped to the selected folder, in API order (newest first): `tiny` cover thumbnail (`getThumbnailUrl` with the cover's `thumbnailUpdatedAt`), title, and subtitle; the first 12 plus a selected later one, then "Show all (N)"/"Show fewer"; "No events yet" when empty. The title is the place ("City, Country", or the country alone when the city is null or equals it; region never shown), else the date range; the subtitle is the date range plus " · N photos", or only "N photos" when the title is the range. Ranges come from the wall-clock `startAt`/`endAt` without zone conversion: "Oct 3, 2023", "Oct 3 – 5, 2023", "Sep 30 – Oct 2, 2023", "Dec 30, 2023 – Jan 2, 2024". Clicking a row sets the `event` filter (the full `EventSummary`; requests send its id) on `photos`, `photoLocations`, `searchPhotos`, and `similarPhotos`, leaving Find similar, Review/Duplicates, and loupe like a folder; it shows as a removable chip with the title under Filters active and as `· <title>` in the search header. Clicking the selected row or the chip clears it. Like `capturedDate`, `event` is a view scope: never saved in smart albums (alone it is not savable) and it deselects an applied album. Terminal scan progress invalidates `events`. The default mocked `events` handler lists none (the fixture library is below the six-photo minimum); `e2e/events.spec.ts` installs `fixtureEvents` (`FIXTURE_EVENTS`, one per display variant) and runs in `Pacific/Kiritimati` (UTC+14) so any zone conversion would change the expected text.
- **Junk review** (`src/hooks/use-junk-review.ts`): the Catalog's **Review** item (below Quick Collection) shows `junkReview` `counts.all`, loaded through a `{ limit: 1 }` request. Selecting it replaces the library with candidates from `junkReview({ reason?, limit: 200 })`, newest first; folder/collection/filters/search are kept but ignored (Filter By is hidden) and are restored when Review is left via the header ✕, a folder, collection, tag chip, search, or Find similar. The header's reason control (All, Screenshots, Documents, Blurry, Too dark) shows library-wide counts; Reject all (N)/Keep all (N) resolve exactly the shown photos, confirming first when N > 50. Grid cells show the first reason; the metadata panel shows "Why it's here" with Reject/Keep. With an active candidate, `X` rejects and `K` keeps through `resolveJunk` (not `setPhotoCuration`) and advance to the next candidate. Resolutions remove photos from every cached review list and decrement counts optimistically, restore both and show an alert on error, then refetch review (plus photo lists after a reject) once no resolution is in flight. Curation and scan completion also invalidate `junkReview`. An empty list shows "Nothing to review".
- **Duplicates** (`src/hooks/use-duplicate-groups.ts`): the Catalog's **Duplicates** item (below Review) shows `counts.duplicate + counts.burst` from a `duplicateGroups({ limit: 1 })` request. Selecting it replaces the library like Review does (Review and Duplicates are one exclusive `catalogView`; folder, collection, smart album, tag chip, search, Find similar, or the header ✕ leave it). The header radiogroup (All / Duplicates (n) / Bursts (n)) sends `kind`. Groups load as an infinite query (`limit: 50`, `cursor` = previous `nextCursor`, "Load more" button) and render as cards of `medium` thumbnails in API order (keeper first) with resolution, file size, RAW badge, rating/pick, and EXIF capture time; the suggested keeper is preselected and badged "Suggested". Clicking a member toggles keep (the last kept member cannot be deselected) and makes it the active photo; double-click opens the loupe, whose navigation and filmstrip walk the shown members. "Keep selected, reject N" sends `resolveDuplicateGroup({ key, action: "keep", keepIds })` and "Not duplicates" sends `{ key, action: "dismiss" }`; both remove the group and decrement its kind count optimistically across cached lists, roll back with an error on failure, and on `CONFLICT` show "This group changed" and let the settle refetch show the current group. Once no resolution is in flight, `duplicateGroups` is refetched; after a keep, photo lists, smart albums, and `junkReview` are too. Curation changes, junk rejections, and terminal scan progress invalidate `duplicateGroups`. Sharpness is not part of the photo DTO, so it is not shown.
- **People** (`src/components/PeopleView.tsx`, `src/hooks/use-people.ts`): the Catalog's **People** item (below Duplicates, `aria-pressed`) shows the visible `people` count and is a third exclusive `catalogView` (the library `photos` query is not requested while it is shown). The view is a responsive grid in API order: a round `getFaceCropUrl(coverFaceId)` avatar (`/api/faces/:id/crop?size=256`), or the name's initial ("?" unnamed) when `coverFaceId` is null; the name, or an "Add a name" button for unnamed people; and "N photos". Clicking a person leaves the view and sets the `personId` library filter (sent on `photos`, `searchPhotos`, `photoLocations`, `gearStats`, and smart albums); the grid shows a "Person: {name|Unnamed}" header with **Leave person**, Filter By shows a clearable chip, it joins Filters active/Clear all, and the search header scope. Each card's "…" menu offers Rename (inline; Enter saves the trimmed name, empty sends `name: null`; Escape or blur cancels), Hide/Unhide (`hidden`), and Merge. **Show hidden** refetches with `{ includeHidden: true }`. Merge mode shows checkboxes; with ≥2 selected, **Merge into...** lists the selection, then a confirmation sheet sends `mergePeople({ targetId, sourceIds })` (the other selected people). Every mutation patches all cached `people`/`person` data optimistically, restores it with a dismissible "Couldn't …: message" alert on error, and invalidates `people`, `person`, `photoFaces`, `photos`, and `searchPhotos`.
- **Metadata People** (`src/components/panels/PhotoPeople.tsx`): for stills (never videos), `photoFaces({ photoId })` lists faces left to right: a 32 px crop (`size=128`), the person's name, "Unknown", or "Not assigned" (rejected), and an assign combobox. Typing filters named people; options are "New person: {typed}" (`{ faceId, name }`), each matching person other than the current one (`{ faceId, personId }`), and "Not this person" (`{ faceId, personId: null }`, omitted when already rejected). Assignment updates the `photoFaces` cache optimistically, rolls back with an inline alert on error, and invalidates people and photo lists.
- **Face boxes**: in the loupe on a still (not video, failed RAW, People, or Live playback), the toolbar's **Face boxes** toggle (`ScanFace`, `aria-pressed`) or `F` draws each `photoFaces` box with its name label ("Unknown" when unassigned) over the image's drawn rect: `contentRect` derives the object-fit letterbox from `naturalWidth`/`naturalHeight` and the element box, recomputed on image load and by a `ResizeObserver` on the image and its wrapper. The toggle persists across photos. Clicking a box opens the right panel if hidden, then scrolls its metadata row into view and focuses it.
- **Map** (`src/components/MapView.tsx`, `src/lib/map.ts`): the toolbar's map toggle or `M` switches to `viewMode: "map"` (persisted with grid/loupe; entering it leaves Find similar, Review, and Duplicates, and Review/Duplicates return to the grid). MapLibre GL JS is lazy-loaded (its own chunk plus a same-origin module worker via `?worker&url`). It renders `photoLocations` for the folder/collection and library filters (not the search query or the current map area) as a clustered GeoJSON source: blue cluster circles with DOM count labels (`map-cluster-count`, so styles need no glyphs) and small point circles; it fits the points whenever the scope changes, and shows "No geotagged photos" when none match. Clicking a cluster zooms to its expansion zoom; clicking a point opens that photo in the loupe. **Show N photos in this area** (N counts loaded points in the viewport) sets the `bounds` filter from `map.getBounds()` normalized by `normalizeViewportBounds` (longitudes wrapped into [-180, 180], `west > east` across the antimeridian, full range when the view spans 360°) and returns to the grid; `bounds` is sent on `photos`/`searchPhotos`, shown as a clearable **Map area** chip under Filters active (Clear all removes it too), and appended to the search header as `· Map area`. Bounds are never saved in smart albums: `toSmartAlbumFilters` omits them, so a map area alone does not offer **Save as Smart Album** and with other filters it is silently left out; an applied smart album deselects while a map area is active. The metadata panel's Location section shows **Show on map** only when `photoLocation` (the API validity rule) accepts the photo; it switches to the map centered on the photo at zoom 14.
- **Timeline** (`src/lib/timeline.ts`): only the main library grid (not search, Find similar, Review, or Duplicates, which keep their API order) is sorted and grouped. Dashboard computes `groupPhotos(listedPhotos, grouping, sort)` once (memoized on the list and settings) and that display order is what the grid, loupe, filmstrip, and arrow keys walk. A photo's timeline date is its EXIF `dateTaken` wall clock (`YYYY:MM:DD HH:MM:SS` or ISO-like, never zone-converted), else `modifiedAt`, else `createdAt` in local time; photos with none form a final "Unknown date" section. Sort `captured` is oldest first with an ID tiebreak; `added` is ascending ID. Grouping `months` (default) or `years` renders sections with sticky headers ("October 2023"/"2023") and a bare photo count; `all`, or sort `added`, renders one ungrouped grid. Group by (Years/Months/All) and Sort by (Captured/Added) are toolbar radiogroups (arrow keys move the choice) shown only for the library grid, persisted as `grouping`/`sort` in `photobrain-library-state`. With more than one year, a year rail at the grid's right edge scrolls a year's first section to the top and highlights the year at the top.
- **Calendar** (toolbar `CalendarDays` button, library grid only): a popover with one month at a time (localized title, locale-first-weekday grid). Each day shows its count of loaded, currently filtered library photos with that EXIF capture day (fallback dates never count, matching the API's `capturedDate`); days without photos are disabled. It opens at the active `capturedDate`'s month, else the newest month with photos; prev/next skip months without photos and are disabled at the ends. Clicking a day closes it and applies `capturedDate` like an On this day card (chip, filtered `photos` request). `Escape` or an outside click dismisses it.
- **Gear stats** (`src/components/GearStatsView.tsx`, `src/lib/gear-stats.ts`): the toolbar's **Gear stats** toggle (`BarChart3`, `aria-pressed`) is offered only while the library grid is shown (not search, Find similar, Review, Duplicates, loupe, or map) and replaces the grid (and its timeline controls and On this day strip) with `gearStats`, sent the exact input of the grid's `photos` query. The header reads "N photos · M with camera data"; Cameras and Lenses are horizontal bar lists in API order (count desc, label asc), top 10 then "Show all (N)"/"Show fewer"; clicking a row sets the `camera`/`lens` filter and returns to the grid. Focal length, Aperture, Shutter speed, and ISO render every API bucket in order as HTML/CSS bars (zero buckets as empty bars) with the count above each bar and `aria-label`/`title` "label: N photos" ("1 photo"). Shots per year rows (year ascending) show the total and a bar segmented by the five cameras with the most photos overall (count desc, camera asc), all others summed as "Other", with a legend; no `cameraYears` shows "No dated camera data". `total == 0` shows "No photos match these filters". Toggling again, a camera/lens row, searching, Find similar, Review, Duplicates, loupe, or map leaves Gear.
- Implemented shortcuts are `G`, `E`, `M`, `S`, `B`, `F` (toggle loupe face boxes on a still), `0`-`5`, `P`, `X`, `U`, `K` (Review only), `Shift+D` (download active photo as JPEG 2048, or a video's original), `Space` (play/pause a loupe video), `Tab`, `Shift+Space`, left/right arrows, and `Escape`. In Review, `X`/`K` resolve the active candidate instead of flagging. Shortcuts are ignored while an input has focus.
- Modifier-click range selection and `Ctrl/Cmd+A` are not implemented. Do not document or test them as supported behavior.
- `src/components/Lightbox.tsx` and `src/components/SearchBar.tsx` are legacy/unreferenced by the active dashboard. Check imports before extending them.

## Runtime Configuration

Development uses `VITE_API_URL`, defaulting to `http://localhost:3000`.

Production runs `serve.ts`, which reads:

- `API_URL`, default `http://localhost:3000`
- `HOST`, default `0.0.0.0`
- `PORT`, default `3001`
- `MAP_STYLE_URL`, unset by default (the client then uses `VITE_MAP_STYLE_URL` or `https://tiles.openfreemap.org/styles/liberty`)

`serve.ts` serves `dist`, falls back to `index.html` for SPA routes, and injects `window.__CONFIG__` (`apiUrl`, plus `MAP_STYLE_URL` when set) into HTML. `src/lib/config.ts` prefers those runtime values, then `import.meta.env.VITE_API_URL` / `VITE_MAP_STYLE_URL`, then the local defaults.

## Styling and Components

The UI uses Tailwind CSS, CSS variables in `src/index.css`, Radix/shadcn primitives under `src/components/ui`, and Lucide icons. Preserve the existing Lightroom-inspired dark/light visual language when adding controls.

`src/components/ui/sidebar.tsx` defines a separate sidebar system. `src/components/Layout.tsx` renders `SidebarTrigger`, but `App.tsx` does not provide `SidebarProvider`; verify non-dashboard routes before relying on `Layout`.

## Thumbnail Rules

Always use `src/lib/thumbnails.ts` rather than constructing image URLs manually:

- `getThumbnailUrl(photoId, size, thumbnailUpdatedAt?)`
- `getThumbnailSrcSet(photoId, thumbnailUpdatedAt?)`
- `getFullImageUrl(photoId)`
- `exportPhotoUrl(photoId, size)` and `exportCollectionUrl(collectionId, size)`, `size: "original" | "2048" | "1024"` (attachment downloads; see Export)

The API resolves the photo's path and serves mirrored WebP files. The optional `thumbnailUpdatedAt` becomes a `?v=` cache-busting query parameter. RAW full-image URLs are served by the API as the `large` thumbnail.

The library grid shows photos in capture-date order, so library-grid assertions use `fixtureGridIds` (`fixtureCapturedOrder`); cat.jpg (11) has no EXIF and sorts by its March 2023 file date. When adding a test:

1. Extend the fixture data in `e2e/fixtures/photos.ts` only when the scenario needs new metadata.
2. Add procedure behavior to `e2e/fixtures/handlers.ts` if the browser makes a new request.
3. Mock binary/image or Realtime routes as needed; do not start the real API for E2E.
4. Run `bun run test:e2e` from this directory.

## Known Gaps

- No web unit-test or real API integration-test script exists.

- The non-dashboard pages (`/preferences`, `/about`) are mostly placeholders and their shared `Layout`/sidebar context should be verified before use. Collections live in the dashboard; there is no `/collections` route.
